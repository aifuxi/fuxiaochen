版本为 v1，制定日期为 2026-10-01。**两页样板已按本基线实施。** 静态稿保留作为目标对照，实际运行检查范围与结果见末尾的“样板实施检查记录”。视觉规范以 [DESIGN.md](../../DESIGN.md) 为准；具体测量和复核方式以本文为准。

## 两页目标结构

### 文章管理

阅读顺序为「标题与新建博文 → 状态、分类与搜索 → 表头与文章行 → 结果数量与分页 → 会话模拟说明」。页首移除英文眉题和重复说明，保留清楚的“内容管理”标题与页面主操作。

- 状态 Tabs、分类 Select、搜索 InputGroup 和可用时的重置入口属于同一工具栏。
- 工具栏与表格、分页共享一层 `surface` 数据容器，不再使用独立筛选 Card 和额外列表 Card。
- 桌面控件按状态、分类、搜索顺序排列，空间不足时换行；手机状态 Tabs 局部横向滚动，分类与搜索纵向排列。
- 表格保留标题与标签、分类、状态、浏览量、时间、操作六列；标题为可编辑入口，正文不放入列表。
- 行自然随内容增高，长中文标题可换行；手机保留六列，仅表格容器横向滚动。
- 新建、编辑、删除沿用现有 Dialog。页面“新建博文”使用 primary；顶栏“新建文章”保留功能，改为 secondary 视觉。

### 系统设置

阅读顺序为「标题与保存所有变更 → 页面级 Tabs → 当前分组的 Sections → 会话模拟说明」。取消整页外 Card、头像舞台和逐条开关 stage；字段使用页面背景、标题、说明、对齐与 `outline` 分隔线组织。

保留三个业务 Tabs：个人资料与站点信息、系统偏好与自动化、高阶开发与 API 凭证。**第一 Tab 内拆成站点信息与个人资料两个 Section，业务 Tab 数量不变。**

| 业务分组            | Section 与字段组织                                                                 | 保留语义                                     |
| ------------------- | ---------------------------------------------------------------------------------- | -------------------------------------------- |
| 个人资料与站点信息  | 站点信息包含站点名称与副标题；个人资料包含头像、昵称、身份头衔、头像地址与个人简介 | 头像预览仍跟随地址更新，失败提供既有替代图标 |
| 系统偏好与自动化    | 评论与备份以连续说明和开关行排列，每页数量为普通字段行                             | 备份只保存演示偏好，不启动实际服务           |
| 高阶开发与 API 凭证 | 保留既有提示、模拟服务与遮蔽凭证、设计系统及字体信息，按业务关系平铺               | 不添加凭证能力，不宣称连接真实服务           |

桌面字段标签在左、控件在右；宽度不足时转为纵向。头像是个人资料普通行中的 56px 预览，不单独形成舞台卡。保存按钮提交所有 Tabs 的草稿，不能只保存当前可见分组。

## 样板实施范围与完成条件

本次按本基线只实施文章与设置两个样板页。优先修改 `admin-posts.tsx`、`admin-settings.tsx` 及其样式；后台共享标题和顶栏创建按钮的样式调整只覆盖这次明确需要的行为。新增后台专用 Tailwind CSS v4 变量时必须同步 `DESIGN.md`，不改写全站展示组件的通用 token。

实施前阅读当前 `node_modules/next/dist/docs/` 中相关指南，用 CodeGraph 重新确认变更范围。继续复用 `components/ui/` 中可组合的 Base UI 组件，静态标注稿的 HTML 不作为生产实现直接粘贴。

验收顺序为桌面默认、手机默认、结构尺寸、交互矩阵、临界宽度与长内容。结构和控件边界必须符合表中数值；字号、行高、内边距与最大宽度以浏览器 computed style 确认；内容驱动高度按自然布局评估，不用固定像素裁切。截图只比较稳定状态，字体抗锯齿差异不能掩盖容器职责或对齐偏差。

不新增预览抽屉、独立文章编辑路由、表头排序、新指标或新的设置业务分组；不扩展仪表盘、媒体库、评论、友情链接或访客日志。两个样板页完成视觉与交互核对后，再决定是否迁移其他页面。

基线制定阶段交付文档、四张对照证据、两页桌面与手机静态标注稿及 `DESIGN.md` 目标规则；样板实施阶段进一步核对实际页面的结构、尺寸与受影响交互。检查通过不等于完成全面无障碍审计。
