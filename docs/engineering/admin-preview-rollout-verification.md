# 后台预览方案实施验证（2026-10-16）

## 范围与实现

用户授权将已调整的预览方案应用到正式后台，同时保留基础设计体系和全部业务功能。
本轮采用指定的 taste skill v2 experimental，参数保持 6 / 3 / 5，依照 DESIGN.md 与
后台场景规范实施。独立预览的方案演进保留在 [预览验证记录](admin-preview-verification.md)，
不能用预览中的模拟操作证明正式持久化流程通过。

正式代码已实现以下布局：

- 文章、友链：顶部横向状态 Tabs、全宽开放列表、具名筛选及排序控件；无表头、条目分割线和常驻分页。
- 分类与标签：顶部 Tabs、分类紧凑块与独立标签云，新增分类使用 Dialog。
- 日志：以留白区分更新条目，条件出现“加载更早更新”。
- 备份：最近执行、自动备份、范围说明三个业务 Card 与开放执行记录；完整校验信息保留在详情。
- 设置：216px 导航、32px 列距、66px 完整分组入口；手机横向导航高 44px，重新载入移到页首。
- Dock：业务与全局操作两段，保留短名称、首页、主题、通知和账户入口。
- 写作：真实 Tiptap 编辑器保留，文章设置改为发布与归类、内容摘要、展示与排序三组。

共享 token、控件基础尺寸和皮肤未修改。没有修改数据库 schema、鉴权、安全规则、
媒体存储或前台页面。新增备份查询排序参数，由服务端对完整结果排序后再分页；
保留旧查询默认值、稳定 ID 次序和空字节数末位规则。

服务端分页接口继续使用。新 `usePagedResource` 按真实批次追加、去重，条件变化取消旧请求，
版本变化或刷新重查当前起始批次；旧 `page` 深链提供前后批次入口。文章进入编辑前记录所在
批次，使返回地址保留位置。友链新增后清筛选、排序和通知定位，再聚焦新记录。
文章、友链和分类保留 8 / 10 / 20 / 50 数量选项；通知中心的原分页不在开放列表改造范围内。
