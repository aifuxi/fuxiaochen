# 后台独立 HTML 预览（2026-10-16）

本文先保留第一版的实现与验证记录；用户反馈后的第二版见文末“第二版：布局重做”。

## 范围与设计依据

本次按用户要求先制作交互预览，使用 karpathy-output-evolution 的自包含 HTML 形式。
视觉依据为当前 DESIGN.md、docs/design/admin.md、共享 token 和本地 Base UI 组件，
不将前一版改造计划中的 28px 标题、16px 连续工作区、设置标签全部上置当作现行规范。

交付文件为 public/previews/admin-workspace.html，可离线打开；开发服务中的访问地址为
http://localhost:3000/previews/admin-workspace.html。默认打开备份页，
也可通过文件内 Dock 切换文章、分类标签、日志、友链、设置和写作页。

预览仅使用内存中的示例数据。主题偏好使用独立的
fuxiaochen-admin-preview-theme 键，不读写正式站点偏好。
HTML 的 CSP 禁止网络连接、外部资源和表单提交；字体、图标、头像、运行时及许可证均内嵌。
未修改正式后台组件、路由、主题文件、数据库或业务接口。

## 现行规范的复用

- 复用项目 Button、Input、InputGroup、Select、Tabs、Switch、Dialog、Menu、Tooltip、
  TanStack DataTable、BrandLogo、MotionProvider 和共享正文排版。
- 共享色盘及组件皮肤直接从当前源码编译，连续工作区保留 14px 圆角；
  后台页标题为 24px/32px，普通控件 40px、compact 36px，窄屏目标至少 44px。
- 桌面保留 72px 悬浮 Dock、左距 16px、内容预留 104px，无顶部栏；
  内容容器最大 1264px。设置保留桌面 200px 标签列、24px 列距与 480px 普通字段宽度。
- 页面、表单、浮层和工作区样式仅用于独立预览，不修改共享 token 数值。

## 第二版：布局重做（2026-10-16）

### 授权与设计判断

第一版主要复现现行后台，用户反馈“感觉还是之前的风格”，随后明确选择
“保留基础设计体系，允许重做页面布局”。本轮使用用户指定的
`taste-skill:design-taste-frontend-v2-experimental` 2.0.0，继续以
`karpathy-output-evolution` 的自包含交互 HTML 交付。

Design Read：面向日常内容维护的极简悬浮工作区；保留 Semi 基础体系，通过任务、
信息主次与操作位置重组形成可见差异。参数为 `DESIGN_VARIANCE: 6`、
`MOTION_INTENSITY: 3`、`VISUAL_DENSITY: 5`。

该 taste skill 明确以展示页及改版为主要场景，因此采用其中审计在先、复用真实设计系统、
减少重复容器、排版层级、交互闭环与浏览器回看的要求；营销 Hero、照片、轮播、
滚动叙事等条目在本后台任务中不适用。按用户约束继续使用项目既有 Base UI、
TanStack Table、Lucide 与 Motion，不引入第二套组件体系。

### 已实现的布局差异

- 备份从单一长工作区改为最近执行、自动备份、执行记录、备份范围四个职责区域。
  记录用本地 DataTable；完整编号、精确字节数与 SHA-256 移入校验详情。
- 文章与友链在工作区内加入 180px 状态导航，搜索与其他筛选放在主列表顶部，
  标题与当前结果数单独成行；<=1200px 改为横向 Tabs。
- 分类以主表格和标签辅区构成约 2:1 工作台，辅区最小 260px；新增分类移到页首 Dialog，
  增加分类搜索；<=900px 改为纵向布局。
- 设置由顶部 Tabs 改为左侧 180px 分组导航与右侧平铺字段；<=900px 恢复横向导航，
  保留原字段顺序、200px 桌面标签列及普通字段最大 480px。
- 日志以 112px 日期／版本列配合内容列，操作靠近标题；手机改为纵向信息组，
  长版本、标题与 URL 自然换行。写作设置分为发布归类、摘要、展示排序三组。

这些布局仅在独立预览中实现。`DESIGN.md`、全局 token、基础控件及正式后台源码未改，
场景文档单独注明预览目标和正式实现差异。
