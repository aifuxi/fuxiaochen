# Passkey 接入验证

验证日期：2026-10-13。范围为单管理员通行密钥注册、登录、列表及删除；密码登录保留备用。采用官方 [Better Auth Passkey 插件](https://better-auth.com/docs/plugins/passkey)，服务端和客户端均为固定版本 `@better-auth/passkey` 1.7.7。

## 实现与存储

- 登录页追加通行密钥按钮；先密码登录，在后台「管理账户」添加通行密钥，可选名称最多 64 字符。删除需要确认，密码始终可用。
- 新迁移 `0002_passkey.sql` 只新增 `auth_passkey`、凭据唯一约束和用户索引，不修改前两条迁移，不更换现有管理员、密码或有效会话。
- 公钥与签名计数存于 SQLite，私钥由设备认证器保管。RP ID 取 `APP_ORIGIN` 的主机名，验证 origin 固定取完整来源；生产 HTTPS，本地 localhost。
- 只开放六个必要插件接口。密码与 Passkey 共享持久化限流，完整 Passkey 登录消耗两次尝试；沿用同源校验、16 KiB 正文限制、固定七天签名 Cookie 和令牌哈希存储。公开登录响应不包含原始令牌。
- 插件负责挑战、WebAuthn 签名及凭据所有权；SQLite 原子消费挑战。选项要求设备用户验证，afterVerification 再校验实际 `userVerified`。
- 每条数据库写入仍使用同步 IMMEDIATE 事务；在官方插件分开的计数更新与会话创建步骤内复核原凭据和密码状态，拒绝验证期间删除、计数变化与密码重置的旧结果。没有自行实现 WebAuthn 验签。
- 密码重置撤销会话并保留公钥；备份恢复保留备份时的公钥，撤销会话并清空挑战。PostgreSQL 来源没有 Passkey，离线导入检查新公钥表为空。

## 验证边界

- 虚拟认证器验证了浏览器原生 WebAuthn 与官方客户端流程；真实 Touch ID、Windows Hello、手机跨设备及云同步认证器尚未由用户实际注册验收。
- 原生取消提示、浏览器不支持分支及列表加载失败重试已实现、仅源码核对；浏览器实际验证了密钥被删除后的失败反馈、解除提交锁和密码备用。
- 本轮未进行生产发布、真实服务器、Portainer Stack 或 linux/amd64 演练。域名与 HTTPS origin 必须在生产配置中确认；变更主机名需要重新注册通行密钥。
- MFA、公开账号注册、密钥改名及敏感操作二次认证不在本次范围。

使用及运维约定见 [产品行为](../product/behavior.md) 与 [认证维护](../maintenance.md#better-auth-认证维护)。浏览器测试使用官方 [Playwright CDPSession](https://playwright.dev/docs/api/class-cdpsession) 和 [Chrome 虚拟认证器](https://chromedevtools.github.io/devtools-protocol/tot/WebAuthn/)，只操作测试浏览器及专用新库。
